NVIDIA 配置详情显卡最大功率 175W；动态增强“是”与官方规格和底层读取一致。
Armoury 首页增强模式；Max TGP 175W当前并非因处在静音模式而只获得较低的官方上限。
手动模式编辑器（未应用）TGP 最高 150W；Dynamic Boost 最高 25W；温度目标 87°C官方界面提供的范围仍止于 175W；查看没有改变当前 Turbo。

定位结论：“为什么最大上限是 175W”已经明确：这是该机型的 OEM 功率策略，由 NVIDIA 驱动及平台固件控制链共同落实。仅凭软件遥测不能把每一瓦的决定唯一归属于 VBIOS、EC 或驱动中的某一层；没有进行逆向固件或强制设限尝试。

另一个问题是“为何某个游戏达不到 175W”：这要用同场景的 GPU 利用率、CPU/GPU 功率、温度、频率和限频标志来判定。本次没有安全条件执行满载复现，因此不能给未提供的游戏表现虚构具体瓶颈。

可能限制本次证据诊断状态
GPU 功率上限最大 175W 已被多处证实；轻负载 SW Power Cap 均未触发上限明确；轻负载没有撞墙不代表满载不会撞墙。
Dynamic Boost / CPU 竞争功能“是”、25W 配置；有效上限 84/85 个样本为 175W，一个为 172.59W存在一次短暂上限调整；不能仅凭该点归因于 CPU、动态策略或服务更新。缺少连续 CPU 功耗与满载联动数据。

整机供电限制用户确认 380W；AC 在线；电池放电率 0；HW Power Brake 未触发轻负载未见外部限功/电池补电迹象；未测插座功率、适配器纹波、接口温度或双烤，不能排除高负载供电问题。
驱动/软件稳定性近期重复 0x141 与 nvlddmkm 错误；当前自动调优关闭需要优先排查。这与“175W 官方上限”是两个不同的问题。

避免误读：nvidia-smi 的 Default Power Limit 为 95W，不表示本机正被锁在 95W，也不等同华硕的 150W 基础 TGP；当前生效和最大值应结合官方动态功率定义阅读。14101MHz 是该传感器的显存时钟显示口径，不是额外计算得到的有效数据率；NVIDIA 详情标称 28.00Gbps。瞬时功率峰值或软件输入框即使出现 225W，也不能证明持续 225W、VRM 余量或长期稳定性。

所有采样的 Reliability 都为 Active，其他已采集的功率、温度、外部供电及 Board Limit 标志为 Not Active。该字段按本机 nvidia-smi 帮助解释为为满足器件寿命可靠性预期而限制频率；它不是“GPU 已损坏”的诊断码，也不应被绕过。初始 SW Power Capping 和 SW Thermal Slowdown 累计计数都为 539,916,314μs，观察后的快照未增加；累计值没有事件温度与时间上下文，不能据此认定此次过热。

5. 225W 可行性与官方更新

官方支持的硬件目标：否。该 G635LX 的公开 GPU 规格是 175W，没有找到针对该型号的官方 225W 认证。380W 适配器额定功率是输入侧供电能力的一部分，不代表 GPU 供电支路、VRM、主板连接、显存和散热系统可承受任意增加的 50W。华硕系列发布资料提到的最高 240W 热设计能力是系统级宣传上限，不能解释为 GPU 可独占 240W，也不是本机当前实测。ASUS 2025 系列发布资料

官方软件可配置目标：否。本机已读到的官方界面和驱动最大值都止于 175W。本结论不是声称所有非官方实验在物理上都不可能；即使第三方运行时工具能改写某个目标，也仍是超规格供电修改，软件上能撤销不代表潜在硬件损伤可逆。本次未尝试任何此类工具、跨机型 VBIOS、分流电阻修改或保护绕过。

与“不牺牲长期稳定性”的目标是否兼容：现有证据不支持。本机已有 GPU 超时；VRM/热点温度和持续双负载供电未验证。额外 28.6% 的功耗也不会线性转化为帧率，CPU、显存、游戏引擎与更高电压的效率损失都会限制收益。

6. 可执行的优化路线、预期收益与风险

以下相对基准是“当前 Turbo、独显输出、原装 380W”。本次没有受控游戏数据，因此除已启用项的新增收益为 0 外，不给没有证据的精确百分比。改善崩溃、卡顿和低帧也属于性能体验提升，但不能冒充平均 FPS 增加。

优先级 / 方案预期效果与收益边界风险 / 恢复方法本次状态
1 · 保持已启用的官方高性能路径Turbo、独显输出和正确适配器已到位；重复切换预计新增收益 0%。独显待机耗电与 Turbo 风扇噪声较高；可从官方界面回原模式，但本次无需改变。已核实，保持。
2 · 建立无额外调优的稳定基线核查所有曾使用的调优工具、游戏配置和频率偏移；NVIDIA 自动调优保持关闭。必要时在官方界面建立零额外核心/显存偏移的对照，先确认 CPU 功率/风扇配置不会同时变化。目标是消除超时；峰值分数可能小幅下降，不承诺增帧。低风险、设置可恢复；保存截图后逐项更改。不要把未应用手动页的 +50/+100 直接当成当前 Turbo 的有效偏移；不要因 UserOC 标签就盲目降压/加压。当前自动调优已关闭；没有改动其他设置。
3 · 单变量驱动排查对比一个合适的官方驱动候选，验证同一故障场景。预期改善兼容性或稳定性；平均 FPS 收益无法可靠预测，可能不变或下降。安装时可能黑屏、需重启、配置重置；先保留当前包和记录，失败则重新安装原版本。默认不使用强制清理、改 TDR 超时等掩盖问题的方法。候选版本已核实，未安装。
4 · 减少无关后台 GPU 工作关闭用户不需要的录屏/叠加层或渲染窗口，逐个验证。当前桌面采样并非纯待机；有后台竞争时可能改善帧时间，没有竞争时约为零收益。可能中断录制或远程会话；GameViewer 等已有程序未被擅自终止。恢复方式是重新启动对应功能。只记录了进程，未停止服务或应用。

7. 稳定后如何补齐同条件测试

这是一份后续验证规程，不是已经完成的测试。若原频率、合适官方驱动下仍出现 0x141，应停止性能探索，优先让 ASUS 分析已保存日志与必要转储。进入测试前应明确最近故障是否仍能复现，避免把一次短测通过当作问题消失。

  1. 固定环境：同一适配器、摆放与散热条件；记录室温、Windows/BIOS/驱动/Armoury 版本、显示模式、电量、后台程序。先让组件安装彻底结束。为避免 CPU/GPU 竞争，关闭确实不需要的程序；不要中断所需远程连接。
  2. 固定负载：可选已有的《赛博朋克 2077》内置基准，保持同一游戏版本、分辨率、画质、光追与 DLSS 设置，基准硬件性能时关闭帧生成。也可使用相同版本/预设的 3DMark；分开报告 Graphics Score 与总分。本机已安装 FrameView，可用于实际游戏帧时间记录；本次没有启动这些测试。
  3. 分阶段：先短时低风险复现，再在无错误且温度受控时逐步延长。完成预热后同场景至少 3 次，取中位数；改变一个变量后重复，并最后恢复 A 再测一次以排除热状态/后台漂移。
  4. 记录：GPU 平均/峰值/持续功率、有效上限、时钟、温度、利用率、各限频原因；CPU 包功率与温度；电池是否补电；平均 FPS、1% low、帧时间与成绩。显存/热点/VRM 温度若工具不提供，写“不可用”，不能用核心温度替代。
  5. 停止门槛：示例保守测试门槛为 GPU 核心 ≥85°C 连续约 10 秒，CPU ≥95°C 持续约 30 秒，或任何热降频/异常外部功率制动、AC 掉线、电池在持续负载下明显异常放电。门槛是提前终止标准，不是制造商损伤温度。任何花屏、驱动重置、黑屏、计算错误或异常气味立即停止，无需等待门槛计时。
  6. 恢复与验收：终止测试程序，恢复本轮唯一修改项及原 Turbo/功率/频率/风扇设置；保存前后日志。成绩增幅必须超过 3 次重复的自然波动且不能恶化 1% low 或错误率。后续延长实际游戏与相关应用验证；即使通过也只是所测试条件下稳定，不是长期寿命保证。
